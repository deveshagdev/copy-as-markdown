# Copy as Markdown — Project Notes

## Goal
Weekend project: a Chrome browser extension, built to learn JS, aiming for
real user adoption first (monetization idea for later, not decided yet).

## What it does
Converts the current webpage into clean Markdown and copies it to the clipboard.
One action, not two: if you have text selected it copies the selection, otherwise
it copies the whole page. Useful for people who take notes in Obsidian, Notion,
or write GitHub issues/PRs.

## Layout
- `extension/` — the extension itself. This is the folder to point
  chrome://extensions "Load unpacked" at, and the only thing that goes in the
  store zip. Nothing else belongs in here: Chrome refuses to load an unpacked
  extension containing names that start with `_` (reserved), and any extra file
  ships to users.
- `testbed/` — local test harness, see Status below
- `tools/make-icons.js` — regenerates `extension/icons/*.png` from code
  (`node tools/make-icons.js`). No image editor needed, no dependencies.
- `PRIVACY.md` — privacy policy, needs to be published at a public URL for the
  store listing
- `.claude/launch.json` — serves the project root on :8765 for the harness

## Stack / architecture
- Manifest V3 Chrome extension, all client-side, no backend
- `turndown` library (vendored as turndown.js) does HTML -> Markdown conversion
- content.js: the converter. NOT a declared content script — it is injected on
  demand by chrome.scripting.executeScript, so it is wrapped in an IIFE behind a
  `window.__copyAsMarkdown` guard and is safe to inject repeatedly. Exposes
  `extract()` (returns {markdown, mode}) and `copy()` (extract + write to the
  page's clipboard). Also adds what turndown itself lacks: GFM table output,
  resolving relative links/images to absolute URLs, and re-wrapping table rows
  when a selection starts and ends inside one table
- background.js: service worker, context menu item; on click injects the scripts
  and calls `copy()`, then reports the outcome via the toolbar badge (✓ / !)
- popup.html / popup.js: toolbar popup with one "Copy as Markdown" button. Calls
  `extract()` and writes to the clipboard *itself* rather than in the page —
  navigator.clipboard needs a focused document and the popup has focus while the
  page does not

### Why on-demand injection instead of a declared content script
A content script injected at page load is orphaned when the extension reloads or
auto-updates: the old instance keeps running but its chrome.runtime is dead, so
sendMessage silently reaches nobody until the tab is reloaded. That bit during
testing (copy stopped working until a refresh) and would bite real users on
every extension update. Injecting per click sidesteps it entirely.
Side benefits: no more `<all_urls>` content script, so turndown is not parsed on
every page of every site, and the store listing asks for less.
- Icons are generated by `tools/make-icons.js` rather than drawn in an editor,
  which sidesteps the "PNGs can't be pasted as text" problem. Edit the script
  and re-run it to change the artwork.

  `python -m http.server 8765` then open /testbed/complex.html).
  `testbed/complex.html` covers a realistic article; `testbed/edge.html` is a

  `<body>` fallback when there is no `<main>`/`<article>`, and script/style

## Content extraction
Page mode takes `<main>`/`<article>`, then drops (a) anything not visible and
(b) nav/form/controls and navigation/banner/complementary ARIA roles. `<main>` on its own is far too weak: on the Wikipedia Lorem ipsum
article it still contains the language menu, tools menu and appearance settings,
and ~70% of the copied markup was collapsed dropdowns the reader never sees.

Deliberate tradeoff: what you see is what you copy. Content hidden behind a
collapsed accordion or an inactive tab is NOT copied. If that turns out to be
wrong for real users, the fix is to only treat *ancestors* as hidden rather than
any hidden node.

Selection mode applies the visibility filter too (a range spanning a collapsed
menu still clones it, so select-all would otherwise drag in every dropdown on
the page), but NOT the nav/role filter — an explicit selection is taken at face
value, so deliberately highlighting a nav menu still copies the nav menu.

Visibility is tested with `Element.checkVisibility()`, not getComputedStyle:
display doesn't inherit, so getComputedStyle reports a child of a display:none
element as a visible block. Chrome 105+.

## Known rough edges
- document.title is emitted as an H1, so pages whose H1 repeats the title give
  two headings in a row. Intentional for now (nice for notes apps), easy to drop.
- <caption> text on a table is dropped
- A table nested inside a table cell gets flattened into that cell (GFM can't
  express nested tables); a list inside a cell flattens the same way
- Shadow DOM content is invisible to innerHTML, so web components copy as empty.
  Would need to walk shadow roots explicitly.
- Lazy-loaded images that keep their URL in `data-src` (with no real `src` yet)
  produce nothing. Could be handled by checking common lazy attributes.
- `<video>`, `<audio>`, `<iframe>` and inline `<svg>` convert to nothing. If a
  selection contains ONLY those, it yields empty Markdown and the extension
  falls back to copying the whole page, which is surprising. Low priority
  because it needs a text-free selection, but worth revisiting.
- Content inside a closed `<details>` is not copied (it is genuinely hidden —
  consistent with the visibility rule, but users may expect otherwise)
- Still noisy on Wikipedia after the visibility filter, because these are
  visible and carry no standard semantics: bottom navbox tables (which also
  convert into garbled wide tables), the category lists, and the `[edit]`
  section links. Fixing these generically means Mozilla's Readability.js (what
  Firefox Reader Mode uses) rather than more hand-written selectors.
